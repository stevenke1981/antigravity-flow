# Shot generation

Read the selected shots, requested mode, reference files, and last recorded job state. Treat the latest user direction and project rules as the source of truth for duration, aspect ratio, resolution, model, number of outputs, and reference coverage.

## Prepare the composer

- **Flow Agent**: Confirm the Agent toggle is active when requested. Check available video defaults and the current confirmation preference without changing it. State the requested settings and verify the actual output configuration from the proposal or job card. If the choice would automatically spend points and you cannot verify it is authorized, stop before sending.
- **Standard composer**: Use the visible Video control and choose Ingredients or Frames as appropriate. Select the model, resolution, duration, aspect ratio, and output count. Check compatibility and the live cost before submitting. Respect any user-required Agent mode instead of switching to standard for convenience.
- Select attachments by name and observe their chips or previews. For Ingredients, describe which images are timed scene references and which ones lock identity or style. For Frames, verify that pictures are in the intended Start and End slots. If a limit conflicts with required references, look for a compatible shot framing or generation mode within scope. Flag the conflict before dropping required assets.

See [Create videos](https://support.google.com/flow/answer/16353334?hl=en) and [Use Flow Agent](https://support.google.com/flow/answer/17093911?hl=en).

## Submit, resume, and verify

1. Submit the authorized shot once and identify a new result or progress card. Record enough evidence to recognize it on resume, such as a visible job or asset link, title, and submission time. If the next shot depends on the actual rendered tail, hold it until the selected take has been checked.
2. Before retrying an error, check the project and active job list for the same request. Retry a confirmed transient failure only within the authorized budget and after addressing any concrete cause. If a corrected attempt produces the same error, record the exact message, preserve the draft, and continue independent work. Keep policy warnings separate from transient failures.
3. Open the selected result and check its settings and motion. Compare identities, props, locations and handoffs to the plan. Look around a suspected jump at closer frame intervals. Correct serious defects through an authorized revision or trimming in post. Retain the source take and track the edit range.
4. If requested, download the verified version and check the file. Record the accepted take, credits when verifiable, and any pending checks. Continue the batch from pending or confirmed failed shots. Resolve ambiguous submissions before issuing them again.
